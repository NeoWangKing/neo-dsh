# AGENT.md — 在这个仓库里干活前先读这个

> 中文速览：Neo DSH 是 DeepSeek Harness 的桌面套件（Electron 外壳 + 第一方插件 + agent 预设 + profile）。
> 规矩：改动先在 **dev 窗口**里给人看 → 人确认 → 才 commit；**只有用户说了才发版**；发版 = 推 tag，**由 GitHub Actions 打包**，
> 不要在本地交叉打包（会塞错平台的 Node 运行时）。改行为的改动必须带测试；中英文文档要一起改；本文件要在同一次改动里更新。

## What this repo is

Neo DSH — a desktop suite around the DeepSeek Harness. The shell is Electron; everything
that makes it *this* product (plugins, agent preset, profile, resources) lives here. The
harness itself is vendored under `apps/desktop/node_modules/@deepseek-ai/`.

| Path | What lives there |
| --- | --- |
| `apps/desktop/src/` | the shell: home resolution/migration, host spawn + watchdog, port guard, safe mode, proxy, settings routes. No Electron imports outside `main.mjs`, so the logic stays unit-testable. |
| `apps/desktop/test/` | unit suites for the above (plain node, run by `pnpm test`). |
| `plugins/*/` | first-party host plugins (`dsh-activity-line`, `dsh-desktop-settings`, `dsh-smart-approval`). |
| `presets/*/` | agent presets. `liangshen` is the shipped one; a preset dir is read as one `agent.cordis.yml` **plus** the `.mjs` plugins it names (`./tool-bootstrap.mjs` …). |
| `apps/desktop/resources/` | build output that ships in the app: `profile-web/` (profile files + patch layer + plugin `vendor/`), `presets/`, `icon.png`, `settings.defaults.yaml`. Generated by `scripts/build-resources.mjs` — never edit by hand. |
| `scripts/` | `build-resources.mjs` (assemble resources), `patch-harness.mjs` (vendored patches), `fetch-node.mjs` (the Node runtime each platform ships), `check-node.mjs`, `dev-window.sh`, `install-release.sh` (install a published release into a local prefix; verifies the sha256, backs up the old tree, refuses while the app runs). |
| `docs/development*.md` | the human-facing development notes, **English and Chinese kept in step**. |
| `docs/roadmap.md` | the user's own backlog (Chinese only, by design): planned work with the implementation traps already noted. Read it before proposing features; add to it when the user asks for something "later". |
| `.github/workflows/build.yml` | CI: builds linux-x64 / macos-arm64 / windows-x64 and attaches artifacts to the release. |

## Non-negotiables (learned the hard way)

1. **Show before you commit.** Every user-visible change goes through a dev window
   (`bash scripts/dev-window.sh`, port 3199, throwaway home) and the user looks at it.
   Then commit. **Never release without being asked.** Releases are batched.
2. **Update this file in the same change.** If a change alters how the product behaves, how
   it is built, or what an agent should know, `AGENT.md` is part of that change, not a
   follow-up.
3. **Behaviour changes carry tests.** Add them to the `pnpm test` chain in `package.json`.
   Evidence over prose: quote the log line, the test output, the digest — not "should work".
   A real check catches real bugs: the mac build shipped a Linux `node` once and only the
   smoke test noticed (`spawn ENOEXEC`).
4. **Don't rewrite files under a running app.** The client watches the bundles it serves and
   reloads a module the moment it changes; a half-written file takes the UI down
   (`scripts/patch-harness.mjs` writes through a temp file + rename for exactly that reason).
   Patch an installed tree only when the user is about to restart, and say so.
5. **Never leave state behind.** Close dev windows, and clean `/tmp/neo-dev-*`. A headless
   run pointed at the app's own `DSH_HOME` writes a *real session* into the user's sidebar —
   give verification runs their own `DSH_HOME` (see `docs/development*.md`).
6. **Both languages, or neither.** Docs and release notes exist in Chinese and English;
   update both in the same commit.
7. **Config before patches.** Prefer a profile patch row (`plugins/*/cordis.patch.yml`,
   `resources/profile-web/cordis.patch.yml`) over editing vendored code. Patch the harness
   only when there is no seam, keep the patch small, and make it fail loudly when its anchor
   moves (`scripts/patch-harness.mjs`).

## How a change is made

```sh
pnpm test                      # seconds; every suite must pass
bash scripts/dev-window.sh     # the user looks at :3199 (throwaway home, isolated Electron profile)
#   …user confirms…
git add -A && git commit       # conventional commits: feat(scope): … / fix(scope): … / docs(scope): …
```

Commit scopes in use: `smart-approval`, `permission`, `models`, `icon`, `shell`,
`patch-harness`, `docs`, `release`.

## How a release is made

**The CI builds the artifacts. Do not build them locally.**

```sh
# 1. bump both versions
#    package.json + apps/desktop/package.json : 0.1.15 → 0.1.16
git commit -m "chore(release): 0.1.16"
git tag v0.1.16
git push && git push origin v0.1.16        # the tag push is what starts the release
gh run watch                                # or: gh run list -L 3
```

`.github/workflows/build.yml` runs one job per platform (ubuntu / macos-14 / windows-latest),
each of which runs `pnpm run resources` (which applies the vendored patches *and* assembles the
resources — calling `build-resources.mjs` alone ships an app without the patches, which is
exactly what every release up to v0.1.16 did), then `scripts/fetch-node.mjs` **for its own platform** and then
`electron-builder … --publish never`, uploads the artifacts, and attaches them to the GitHub
release with `softprops/action-gh-release` — but it does **not** write the release body.

So the steps that follow the CI:

1. Confirm five assets are `uploaded`:
   `gh release view v0.1.16 --json assets -q '.assets[] | "\(.name) \(.size) \(.state)"'`
2. Write the notes the CI left empty — Chinese first, then an `## English` section:
   `gh release edit v0.1.16 --notes-file /tmp/release-notes-0.1.16.md`
3. Update the machines that run it (macOS: download the asset, check its sha256 against the
   release digest, replace `/Applications/Neo DSH.app`, smoke it).

Cross-building is a trap: `fetch-node.mjs` fetches the *host's* runtime when run without
arguments, so a mac or win artifact built from a Linux checkout ships a Linux `node` and dies
with `spawn ENOEXEC`. The CI gets this right per platform; a local attempt has to pass
`--platform/--arch` and still lacks the target's native rebuilds.

A local `pnpm run dist:linux` is fine for a smoke test before tagging: run
`DSH_DESKTOP_SMOKE=1 DSH_HOME=/tmp/… DSH_DESKTOP_PORT=32xx` against
`apps/desktop/release/linux-unpacked/neo-dsh` and expect one `SMOKE OK:` line.

## What the product ships (quick map)

- **Permission presets** (`resources/profile-web/cordis.patch.yml`, row `permission`):
  `read-only`, `workspace-write`, `smart-approval` (default), `danger-full-access`.
  `smart-approval` is the middle: `sandbox: workspace-write` + `approval: ask`, with the
  per-call reasoning in `plugins/smart-approval/` — allowlist (reads, project scripts,
  dependency fetches, in-workspace writes) → allow; blacklist (privilege escalation,
  irreversible deletion, system changes, leaving the workspace, pipes into interpreters) →
  ask; everything else → the session's own model answers ALLOW/ASK. The guard also **stands
  down** when the session's policy is `never`: an `ask` there is refused before any answerer,
  so asking would silently override the preset the user chose.
- **Model catalog** (row `llm-deepseek`): one `DeepSeek-Flash` (text + images, 1M context)
  and `DeepSeek-V4-Pro`. `models` replaces the whole catalog, so both entries are written
  out; a session pinned to an id no longer listed still runs, it is just absent from the
  picker.
- **Agent preset**: `presets/liangshen` (梁神模式). Its `tool-bootstrap.mjs` keeps the first
  request on the Minimal tool pair and opens the full catalog after the first durable tool
  call; `compaction-epoch.mjs` re-arms that after a compaction.
- **App icon**: `apps/desktop/build/icon.png` (1024, what electron-builder derives platform
  icons from) and `apps/desktop/assets/icon.png` (512, the window icon). Both are
  composed, not drawn in code: the whale-girl art (`~/Downloads/dsh.png` on the user's
  machine) fills the canvas, with a navy `NEO` speech bubble at her upper left. The
  bubble and its tail are **one mask** — the tail's base sits inside the rounded body and
  the union is dilated for the outline — because a rectangle plus a triangle reads as two
  shapes, and a stroked-then-filled tail comes out hollow when the outline is thick
  relative to the tail. The composing script is not in the repo; redo it from the source
  art if the icon ever changes.
- **Vendored patches** (`pnpm run patches:check`): open-in-app Linux icon ids, the 智能批准
  composer glyph, and the sandbox-mode check in `dsh-terminal-bash` that closes a session's
  persistent shells before a preset switch (the harness refuses the change while a PTY is
  alive, which used to block switching presets mid-conversation).

## Shell gotchas worth keeping in mind

- **The updater uses Electron's `net.fetch`, never the global one.** Node's `fetch` carries its
  own CA list and only honours `http_proxy` when `NODE_USE_ENV_PROXY` was set *before* its
  dispatcher existed, so from a desktop launch the request goes direct — behind a proxy that
  intercepts direct traffic that fails as `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` while the browser
  (system proxy, system trust store) is perfectly happy. Measured on this machine: global fetch
  → that error; `net.fetch` → HTTP 200, from the same Electron process with the proxy variables
  removed. `update-logic.mjs` keeps `fetchImpl` injectable; `main.mjs` wires `net.fetch` in.
- **Anything the shell does over the network has the same choice to make** — the proxy env the
  shell applies to itself is not enough for Node's own HTTP stack.

## Data and paths

- App home: Linux `$XDG_DATA_HOME/neo-dsh`, macOS `~/Library/Application Support/neo-dsh`;
  `DSH_HOME` outranks the stored pointer in `desktop-config.json` (Electron userData).
- The app home is seeded from `resources/` on first launch and **never overwritten**:
  `syncBundledPlugins` adds missing plugins, `copyMissingEntries` adds missing presets,
  `syncProfilePatch`-style overlay (see `src/profile-patch.mjs`) hands the shipped patch
  layer to the host as `--patch` for entries the live profile file does not already name.
  A home migrated from `~/.dsh` keeps its own files — that is how 智能批准 went missing once.
- Logs: `<home>/desktop.log` (shell + `[host stdout]`, including the plugins' audit lines);
  sessions live in `<home>/sessions/<cwd>/session-<id>/session.v3.jsonl.zstd`.
